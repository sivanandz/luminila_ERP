## Residuals / follow-ups

1. **AI-SYS-18 secret encryption** — still stores e-way client secret/password as plaintext `store_settings` fields. `tenant-secrets.ts` is server-only and there is no e-way credentials API route in this task's write scope. A server route (auth + `settings:update` gate, `encryptSecret`/`encryptProviderKey`) is required; `eway-bill.ts` (out of scope) must then decrypt on read.
2. **AI-SYS-02 cross-tenant id detection** is best-effort: under PocketBase rules a foreign id's `getOne` returns 404, so the subsequent create hits the id uniqueness constraint and is counted/reported as `failed` rather than `skipped`. It is never overwritten.
3. **Restore timestamps** — PB system fields (`created`, `updated`) are stripped so restores do not depend on whether the server accepts them; restored rows carry restore-time timestamps. Audit content is preserved.
4. **AI-SYS-15** uses `Builder::on_page_load` (re-injection per navigation) rather than creating the window programmatically with `initialization_script`; the window is declared in `tauri.conf.json`, and rebuilding it would be a larger change. Functionally the token now survives navigation.
5. **AI-SYS-13** does not migrate snapshots stored under the old unsuffixed keys; after upgrade the page reports “Last snapshot: never” until the next scheduled backup. Old keys are left in place (they could belong to another tenant on the same browser).
6. **AI-SYS-22 notifications** are browser-local preferences (tenant-scoped key) because no notifications backend exists; they are not sent to the server.
7. **Case sensitivity of `account_email`** — all new filters use the lowercased tenant email (`accountScopeEmail()`). Rows written by older code with a mixed-case `account_email` will not match an equality filter and therefore will not be exported/read; re-saving them under the current client (which stamps lowercase) fixes the row. No data is deleted.
