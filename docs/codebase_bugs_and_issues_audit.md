## Cross-Cutting Root Causes (Fix First)

1. **Dual-Layer Tenant Isolation (`[tenant-dual-layer]`) Bypassed Across Data Layer:**
   Because server routes and admin sessions authenticate as PocketBase `_superusers` (bypassing DB API rules), any query missing an explicit `account_email` filter leaks or mutates records across tenants. In addition, several `.create()` calls (`createProduct`, `createVariant`, `createOrder`, `createChallan`, `createChatProduct`, `logActivity`) omit `account_email`, making new records invisible to scoped reads or rejected by downstream checks.
2. **Staff Accounts (`users.email !== users.account_email`) Locked Out or Fragmented (`A-01`, `A-06`, `A-16`, `AI-SYS-08`):**
   `createAppUser` omits `is_active: true` (blocking staff login via `authRule`), PocketBase rules check `account_email = @request.auth.email` instead of `@request.auth.account_email`, and client helpers filter by `pb.authStore.model?.email` instead of the tenant owner's `account_email`.
3. **Unauthenticated Free-Order & Payment Replay Holes (`POS-01`/`SF-02`, `SF-01`, `SF-03`, `WA-01`/`WA-02`):**
   - `/checkout/whatsapp` calls operator-only `/api/pos/payment` (always 401 for buyers) and its `else` branch marks the flash drop paid/confirmed without payment.
   - `confirmStorefrontPayment` falls back to `confirm.razorpayOrderId` when `order.gateway_order_id` is empty, allowing a ₹1 payment signature tuple to mark any high-value order `PAID`.
   - `razorpay.ts:createPaymentLink` returns `success: true` with a fake `plink_test_*` URL when credentials are unset.
4. **Statutory GST & Stock Ledger Drift (`POS-05`, `ORD-02`, `ORD-05`, `ORD-06`, `INV-05`, `INV-06`, `FIN-06`–`FIN-08`):**
   - `splitInclusiveLine`/`splitExclusiveLine` use `Math.floor(baseTax / 2)` and `baseTax - cgst`, producing unequal intra-state CGST and SGST on odd paise (rejected by GSTN).
   - Storefront orders store GST-inclusive `unit_price` without `tax_rate`, and `generateInvoiceFromOrder` adds 3% GST on top again.
   - B2B orders and manual invoices never deduct `product_variants.stock_level`, while `approveCreditNote` unconditionally adds stock back.
